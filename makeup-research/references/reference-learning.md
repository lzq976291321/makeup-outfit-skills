# 从参考图积累妆容与美甲风格

用户说“研究这张妆容”“提炼下来”“沉淀成 Skill”“根据这张改进”等，即进入分析与沉淀流程。只要求分析时返回分析；要求沉淀或更新时才修改本地 Skill。生成、提交和推送分别遵循本轮授权，不把看到图片等同于执行全部操作。

## 观察与归因

1. 先确认图片可读取，记录来源与用户关注区域。图不清楚或被遮挡时标记无法判断，不补造细节。
2. 按区域记录底妆明度与冷暖、腮红范围、眼影层次、眼线与睫毛、唇色、反光位置与颗粒。区分实际可见效果和灯光、滤镜、后期假设。
3. 若有美甲，记录甲型、长度、底色、透明度、渐变、亮片尺度、立体装饰及其位置。检查甲床到甲尖的连续性、厚度与手指动作，不把修长手指归因为美甲效果。
4. 提炼关系而非只罗列单品，例如“低饱和底色衬托眼角集中亮点”“唇色与腮红呼应，美甲作小面积对照”。说明适用画幅、光线和可替换项。
5. 耳环、项链、戒指等作为妆容周围的亮点与配色关系记录；其款式、佩戴结构和衣领协调由穿搭 Skill 研究。综合任务按用户重点选主流程，另一侧只补相关字段。

## 新增与迭代

- 将新妆容写为独立 `references/styles/<descriptive-slug>.md`，从本 Skill 的“风格索引”增加相对链接。先检查索引；已有相同规律时更新同一案例，保留有意义的差异，不按每张图重复建 Skill。
- 冷白透粉是未指定风格时的招牌默认。用户要求研究或复现新参考时，以新图的颜色、质地和意图为准，不先套冷白妆再分析；新案例不自动替换招牌默认。
- 单张图的观察可成为候选配方，不能升级成普遍规律。分别记录“仅分析 / 已试图 / 用户认可”，并说明认可的是哪个版本、哪部分。只有已有生成结果时才写实测。
- 用户指出问题时，更新对应参数、修复方法与限制；不要为单例缺陷在主文件叠加绝对禁令。主文件只保留稳定、影响决策的规则。
- 保存可迁移描述和用户反馈即可；公开仓库默认不包含人物照片、本机绝对路径或私有来源链接。需要视觉附件时按用户授权处理，不自动上传原图。

## 风格卡模板

```markdown
# 风格名称
状态：仅分析 / 已试图 / 用户认可
来源：用户提供参考图的非敏感说明；不依赖聊天历史才能理解
目标：一句话说明要保留的视觉效果
可见观察：分区、色彩、边缘、反光、纹理
推断与不确定项：灯光、滤镜或遮挡限制
关键关系：哪些元素互相衬托，为什么有主次
参数：底色、红晕、眼妆、唇、美甲、光泽、强度
固定项与可替换项：身份特征保持；颜色、光线等按目标变化
提示词：有身份图与无身份图的可执行版本，删除未使用槽位
检查：人物一致性、妆面定位、甲片结构、曝光与肤色衔接
反馈与修订：实际变化、用户评价、仍未验证范围
```

代表性输入：“这张暖棕哑光妆很美，提炼一下”——建立暖棕哑光候选配方，不强行加入粉色细闪；没有图片时说明缺失，不能宣称已观察。
